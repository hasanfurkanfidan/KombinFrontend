# Accessibility audit (Task A1)

Accessibility is a launch condition. The six tasks that must work for a screen-reader user, a low-vision user and anybody on large text:
**sign in · add a wardrobe piece · settle today's outfit · compare prices and go to a seller · change settings · delete the account.**

This file was written **before** any code change (commit 1) and updated with the outcome of each finding after the fixes (commit 2): the
_Status_ column says `fixed`, `open` (with why) or `device` (cannot be judged without a phone).

## How this was checked

| Method                                                                                             | What it covers                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Code reading** of all 41 route files, the 20 shared components and the screens they mount        | names, roles, states, order, timers, gestures, `numberOfLines`, fixed heights                                                                                           |
| **AST scan** (TypeScript compiler API over `src/` and `app/`, 139 interactive elements, 28 images) | every `Pressable` / `PressableScale` / `Switch` / `TextInput`: label, role, resolved style size, `hitSlop`; every `AppImage`; every title-sized `Text` without `header` |
| **Token arithmetic** (WCAG relative luminance on `src/theme/tokens.ts`)                            | contrast of every text and graphic pair in use; now a unit test                                                                                                         |
| **Jest + RNTL**                                                                                    | what a test can see: label, role, state, `accessible`, live regions, announcements                                                                                      |
| **Needs TalkBack / VoiceOver**                                                                     | focus order and return, announcement timing, sheet focus trap, real text scaling: listed under "Needs a device"                                                         |

Severity: **blocks** = a core task cannot be done or its failure cannot be noticed · **hinders** = doable, but harder or confusing · **polish**.

## 4. Contrast (computed from `src/theme/tokens.ts`)

WCAG 2.2 relative luminance; text needs **4.5**, large text (≥ 24 px, or ≥ 18.66 px bold) and meaningful graphics **3**. The unit test
`__tests__/a11y/contrast.test.ts` repeats this table and fails below the limit.

| Foreground (use)                           | on `bg` | on `surface` | on `primarySoft` | on `chalk` |
| ------------------------------------------ | ------- | ------------ | ---------------- | ---------- |
| `ink` (text)                               | 17.15   | 15.41        | 14.75            | 14.02      |
| `ink2` (body on panels)                    | 10.33   | 9.29         | 8.89             | 8.45       |
| `muted` (captions, placeholders)           | 5.95    | 5.35         | 5.12             | 4.87       |
| `primary` (links, selected, "Sana uygun")  | 8.75    | 7.86         | 7.52             | 7.15       |
| `chalkInk` (text on chalk, bell badge)     | 9.24    | 8.30         | 7.94             | **7.55**   |
| `danger` (errors, sold out)                | 6.46    | 5.80         | 5.55             | 5.28       |
| `chalkLine` (dashed edge, graphic)         | 3.98    | 3.57         | 3.42             | 3.25       |
| `control` (borders, switch track, graphic) | 3.45    | 3.10         | 2.96             | 2.82       |

On fills: `onPrimary` on `primary` 8.75 (pressed 11.25), `onDanger` on `danger` 6.46. Fails: nothing. `control` on `surface` was 2.79 and is 3.10 since the owner's change below; on `primarySoft` and `chalk` it is not used for borders. Muted text on chalk (4.87) passes narrowly; the test guards it.

**Token change applied (owner's decision, 16.11.2026):** `control` `#8D948E` → `#858C86`.

| Token     | Before                                 | After                                  |
| --------- | -------------------------------------- | -------------------------------------- |
| `control` | `#8D948E`: 3.11 on bg, 2.79 on surface | `#858C86`: 3.45 on bg, 3.10 on surface |

The same neutral grey, 4 % darker; white, moss green `#075726`, chalk `#F7E9A7` and Archivo are untouched, and the white fill of a control
on a panel still carries its edge. `contrast.test.ts` now requires `control` on `surface` to pass 3:1. `docs/design/identity.md` records it.

## 6. Needs a device (TalkBack and VoiceOver)

1. Reading order of the home screen (greeting → search → style → size question → daily card → grid) and of the product detail (image overlay buttons first).
2. Focus **moves into** every sheet and **returns to the opener** on close (about 15 sheets); the Android `Modal` back gesture.
3. Announcement timing and duplicates: the Android live regions against the iOS `announceForAccessibility`; the toast and the home card at once.
4. The custom actions (alert settings / delete, tag dot move) appear in the actions menu and work.
5. The hand-built trip date grid (K12) and the Lens region outlines read sensibly with a real photo.
6. Real text scaling at 1.3, 1.5 and 2.0 on a 360 pt and a 390 pt phone: product detail bar, tab bar, daily card, filter chip rows, the confirm sheet, delete screen. (Jest cannot lay text out; the fixed-height and one-line patterns that would fail were removed or capped by reading the code.)
7. Legibility of white text/outlines over arbitrary photos (Lens, post tag dots, discount pill).
8. Reduce motion: the OS setting against the swipe deck, the `Modal` slide, the `search` fade transition and tab changes (the last three are the OS's own).
9. Pull-to-refresh and the infinite lists: does each new page get announced? (Not done; polish.)
